# 03 · Pick the one thing

**Step 3 of 7 · Phase: Awake · Output: the wave-1 workflow and a go/no-go.**

One workflow at a time, never the company. This page decides which one. Winnable and reversible beats impressive: the first workflow is not the one that would look best in the annual report, it is the one where the method can be proven and the proof cannot be argued with.

## The selection criteria

Score the candidate against all six. Use the map from step 1 to answer; guesses are not scores.

| Criterion | What it means | Yes / No | Evidence from the map |
|---|---|---|---|
| Highest ratio of coordination to judgment | Most of the work is moving things between people and systems, not deciding. Coordination is what the Cut removes and what agents absorb; judgment stays human and does not scale the same way. | | |
| High-volume | It runs often enough that a 10× change in cycle time is visible within the sprint, and often enough to produce overrides to learn from. | | |
| Rule-clear | The rules can be written down. If nobody can say what "done" means, you cannot benchmark it. | | |
| Measurable | Cycle time, error rate, and cost can be captured before and after, by the same method, without a project to build the measurement. | | |
| Reversible | If the edge fails, the old way is still there and nothing irreversible happened to a customer, a contract, or a ledger. | | |
| Low regulatory exposure | An error in the shadow run is an internal event, not a filing. | | |

Between two candidates that pass, take the one with the higher coordination-to-judgment ratio.

## The 10× bar

Cycle time is the master metric, and 10× is the bar. Before you pick, estimate the best case honestly: if everything nobody owns is deleted and the survivors are rebuilt on a blank sheet, how much faster does the workflow get?

If the best case is a 10 to 20% improvement, the workflow does not qualify. That is optimization. The method is not worth running on it, and running it there will teach the organization that the method produces 15%.

```
Candidate workflow: [name]
Current cycle time (measured, not recalled): [value]
Best-case cycle time after the Cut, before any automation: [value]
Ratio: [current / best case]
Qualifies (ratio of one order of magnitude or more): [yes / no]
```

## What a good first workflow looks like

Derived from the criteria, not from a list of industries:

- Most of its elapsed time is waiting, handoffs, re-keying, and approvals, not thinking.
- It runs daily or weekly, so a sprint of a few weeks sees hundreds of runs.
- The people who run it can state the rules, even if the rules are currently spread over six documents and two heads.
- Its inputs and outputs already exist in a system somewhere, so before/after can be measured.
- A wrong output is caught downstream and corrected, not shipped to a regulator.
- The best case is one to two orders of magnitude, not a percentage.

## What a bad first workflow looks like

- Every step is a judgment call; deleting the coordination leaves the workflow the same length.
- It runs a few times a quarter, so nothing can be proven inside the sprint.
- Nobody agrees what a correct output is.
- Errors are irreversible, public, or regulated.
- The best case is 10 to 20%.
- It is the flagship: the one whose owners have the most to defend, in a mature core or an acquired unit where the people have had another life before. The method fails there first, and that is an argument for the edge, not for starting there.
